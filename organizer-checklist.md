# Checklista prowadzącego

## Przed szkoleniem

- [ ] uczestnicy mają konta GitHub,
- [ ] uczestnicy są dodani do organizacji `kc-sspw`,
- [ ] uczestnicy są dodani do zespołu `training-azure-2026`,
- [ ] uczestnicy mogą tworzyć repozytoria zgodnie z ustalonym modelem,
- [ ] ustalona jest konwencja nazw: `training-azure-102026-<login>`,
- [ ] środowisko Azure używane na szkoleniu jest gotowe,
- [ ] wiadomo, jaki sposób uwierzytelnienia do Azure będzie ćwiczony.

## Podczas szkolenia

- [ ] każdy tworzy własne repozytorium,
- [ ] każdy przygotowuje prostą aplikację Node.js,
- [ ] workflow GitHub Actions powstaje samodzielnie,
- [ ] sekrety nie trafiają do repozytoriów,
- [ ] uczestnicy uruchamiają i diagnozują własne workflowy,
- [ ] każdy wykonuje deployment do Azure.

## Po szkoleniu

- [ ] każde repo uczestnika ma czytelne README,
- [ ] uczestnicy dodali wpis do `participants/`,
- [ ] finalne workflowy zostały skopiowane do `archive/`, jeśli chcemy je zachować,
- [ ] repozytoria uczestników zostały oznaczone jako szkoleniowe,
- [ ] niepotrzebne zasoby Azure zostały usunięte lub wyłączone,
- [ ] niepotrzebne sekrety i poświadczenia zostały unieważnione,
- [ ] zdecydowano, które repozytoria uczestników archiwizujemy.
